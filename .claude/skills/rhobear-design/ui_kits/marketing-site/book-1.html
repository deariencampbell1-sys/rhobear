LESSON 1.1

The loop that built a company.

"Every feature — big or tiny — goes through the same six gates. No exceptions."

There's no special shortcut for a small fix and a big feature. Both run the same loop: Goal → Plan → Build → Review → Verify → Ship. The owner states the goal, the Architect turns it into a brief, the Foreman builds one lane alone, Neo reviews with fresh eyes, the owner watches it work with their own eyes, and only then does it ship. Then it repeats.

Six roles. Six gates. Nothing skips a step because it looks obvious — the loop is the discipline, not a suggestion.

◈ Scar — a real one
The day "done" wasn't done.

A dispatcher wrote a brief with a path it never opened. The builder built against a file that looked right and wasn't — a stale duplicate sitting one folder over. Every check went green. The PR merged clean. But the live product still showed the old thing, because nobody had opened it with their own eyes. The lesson that built the doctrine: a dispatcher verifies the exact file before it goes in a brief, and "done" means someone watched it work — not that the diff looked right.

LESSON 1.2

A brief is a contract.

"You don't tell it 'build me an app.' You write a brief it can't wander out of."

A brief is a contract, not a wish. It names the exact files — verified, not guessed — the ordered steps, and the part that matters most: acceptance criteria the AI can't fake. "Code compiles" isn't acceptance. "Click X, watch Y happen" is.

What makes a brief safe to send to a builder?

LESSON 1.3

Waves: parallel lanes, zero chaos.

"Eight builders, zero collisions — because nothing starts before what it needs exists."

Big builds get split into waves — independent lanes that run in parallel and hand off by dependency. Wave 0 lays the foundation everything else needs; nothing after it can start until it's done. This is how one person runs six builders at once without anyone stepping on anyone else.

◇ Checkpoint 1.3
Wave 1 needs Wave 0. Wave 2 needs both Wave 0 and Wave 1. What's the only legal start order?
Right. Dependencies point backward, never forward. A wave can only start once every wave it depends on already exists — that's the whole rule, no matter how many waves are running.
LESSON 1.4

Be Neo.

"Fresh eyes, every time. No memory of last week's excuses."

Neo is the gate. Every change gets a reviewer with no memory of last week's context — because stale context defends stale decisions. Neo reads the whole diff, checks the claims himself, and returns one of four verdicts: ACCEPT, FIX-FORWARD, BOUNCE, or ESCALATE. Nothing merges without it.

Why does every PR get a reviewer with no memory of last week's context?

LESSON 1.5

Spot the lie.

"A green checkmark isn't proof. It's just a green checkmark."

A passing test, a 200 status, a screenshot, a green dashboard — every one of them can lie, point at the wrong thing, or just be stale. There is exactly one proof that counts: hitting the real product yourself and watching it work.

LESSON 1.6

One version, one owner.

"Two copies of billing isn't redundancy. It's a bug waiting for a Tuesday."

There is exactly ONE copy of any piece of business logic, and it lives with the product whose name matches. Calendar, booking, payments — they live in Blueprints, and only Blueprints. Every other app calls it. Two copies means drift, and drift is the thing that eats a whole day.

LESSON 1.7

Sellable by default.

"If a stranger buys it, does every value in it still make sense?"

Every shippable thing has to be buyable by someone who inherits nothing personal of yours — no founder email, no personal key, no "boss is special" default. A scanner checks for it before anything ships. Here's the real bug that taught the rule.

◇ Checkpoint 1.7
Why can't the founder's real email be a default in a customer's install?
Exactly. Sellable-by-default. Ship a stranger a product, and every value inside it needs to make sense for THEM — not carry a hidden piece of you along for the ride.
LESSON 1.8

Plan mode → chain mode.

"You type a goal. The plan becomes the thing that runs it."

This is the owner's own move, built into the product. Type a goal into Notes and it becomes wave rows — each one a fenced rho-wave block that IS a dispatchable brief, not just a description of one. Tap Dispatch and it spawns a fresh Hub thread with the right worker. Chain mode runs the whole ladder on its own — reviews up top, Neos down low — merges still wait for you.
