LESSON 3.1

The journey of one message.

"You type 'build me a login page.' Six hops later, code lands in front of you. Let's follow it."

Nothing about the Hub is magic — it's a relay. You type in WorkView, and that keypress becomes a real function call, Api.chatStream(), that leaves your screen and goes looking for help. Every stop on the way is a real piece of code you could open right now.

It hits a local relay first — the shim, listening on port 7456 — which hands it to the engine router. The router's only job is picking the right model for what you asked. Then the model does the actual thinking, and the answer streams back the way it came: tool calls as live chips, and if it wrote code, a diff waiting in the canvas for your Apply or Reject.

LESSON 3.2

Local vs cloud — two bodies, one brain.

"Every product has two bodies. One's a taste. One's the whole meal."

The Hub has a cloud twin called the Workbench. Same crew, same brain — but the cloud body is metered and stripped down, built to be a free taste that hooks you. The local body is the whole meal: your own AI subscriptions, local models, and chain mode — the full autonomy stack.

And it only flows one direction. Cloud decisions are built from what already works locally — never the other way around. Local always unlocks more, because local is where the real capability lives.

LESSON 3.3

The cloud topology — where things actually run.

"Nothing you use is ever directly on the internet. Here's the actual map."

When you hit a RHOBEAR product, your request doesn't land straight on a server — it lands on Cloudflare first. Cloudflare hands it to Caddy, a guarded front door running on one of two real machines. Caddy is the only thing with a public face; everything behind it only listens on localhost.

Two hosts do the actual work: plans-cloud on Google Cloud runs the Plans app. rhobear-vps on Hetzner runs the Workbench, the model gateways, Rho, and the Langfuse tracing. Click through the map below — it's the real one.

LESSON 3.4

Credits — how a token becomes a number.

"$0.0006. That's what one credit actually costs us to deliver. Here's how a message turns into that number."

One credit is priced at $0.00075 but really costs about $0.0006 in real model spend — a thin 20% margin at launch, not a markup grab. But credits meter more than raw tokens. A scheduled cron firing costs 5 credits. A cached render costs 2. Nothing automated is free to us, so nothing automated is free on the meter.

Every message also gets weighed by which rung it uses: Core for cheap everyday replies, Summit for reasoning, Peak for the heavyweight jobs. Try it below.

LESSON 3.5

The money model — how a business is actually built.

"Build cost: $1,010, spent once. Run cost: ~$150/month, forever. Here's why margin gets better as you grow, not worse."

There are two totally different numbers people confuse. Build cost — the $1,010 it took to make RHOBEAR — is spent once and owned forever. Run cost — about $150 a month in servers and model spend — is the property tax, paid every month whether there's 1 user or 1,000.

That's the whole trick to the margin curve. The $150 nut is basically flat no matter how many people sign up. Breakeven lands around 15 subscribers — and every subscriber after that spreads the same fixed cost thinner, which is why margin climbs instead of shrinking.

LESSON 3.6

Build chains — how source becomes a shippable app.

"JSX. Python. Rust. Somehow it becomes one signed .exe you can double-click. Here's the assembly line."

The Hub starts life as three different languages that don't know about each other: React JSX for the screens, Python for the shim, Rust for the native shell. A build chain turns that pile into one installer: build the UI, build the Rust shell, stage the payload — shim, engine, catalog, model runtime — then wrap it in Inno Setup and sign it.

Here's the part that trips people up: the UI ships as plain files sitting next to the .exe, loaded by a webview at runtime — it's not compiled into the binary. Convenient for hot-swapping in dev. Expensive in production: it means a UI-only change still needs a whole new signed installer today.

The build that shipped yesterday's screen.

-SkipBuild looked safe — the files were already sitting on disk, so surely they were current. They weren't. LESSON 3.7

Observability — how we know it's working.

"You can't improve what you can't see. Every AI turn leaves a paper trail."

Every single AI turn gets traced by Langfuse — cost, tokens, latency, broken into spans. A typical voice turn averages about $0.0004. That number only exists because someone bothered to measure it. Without a trace, "it feels slow" or "it feels expensive" are just guesses.

Safety gets the same treatment. Every safety-checked call stamps an x-rhobear-safety header — proof, not a promise, that the safety prompt actually ran on that request.

◇ Checkpoint 3.7
Why stamp a header on every safety-checked call instead of just trusting the prompt fired?
Exactly — trust but verify. A prompt you can't observe is a prompt you're hoping worked. The header turns "it should have run" into something you can actually check.
